# flint3-explorer

Web UI for exploring [flint3-probe](../flint3-probe) JSON output. Runs entirely in the browser — no server, no data upload — and supports side-by-side comparison of up to 4 probe runs.

## Features

- **Multi-file comparison** — drop 1 to 4 probe JSON files, compare side-by-side on shared relative-time axes
- **Metric coverage matrix** — grid showing at a glance which metrics have data in which files
- **Filters** — by importance (critical/important/optional), band (2.4/5/6 GHz/global), client MAC, and free-text search
- **Neighbor detail tables** — per-band aggregation of all BSSIDs seen, sorted by signal, grouped by router (BSSID fingerprint or hostname)
- **Client-vs-client comparison** — optional per-band overlay of all connected clients for each per-station metric
- **Collapsible sections** — starts collapsed; expand what you need
- **State block for `operating_channel`** — labelled fields with cross-file agreement indicators

## Prerequisites

- Node.js 18 or newer ([download](https://nodejs.org/))

That's it. All other dependencies are managed by npm.

## Quick start

```sh
# Clone or copy this directory, then:
cd flint3-explorer
npm install    # first-time setup — installs React, Vite, Recharts (~200 MB in node_modules)
npm run dev    # starts a dev server on http://localhost:5173 and opens the browser
```

Save any file in `src/` and the browser hot-reloads automatically. Fast iteration loop.

## Building for distribution

```sh
npm run build
```

Produces a self-contained `dist/` folder. Contents:

```
dist/
  index.html
  assets/
    index-<hash>.js         (React + Recharts + explorer, minified)
    index-<hash>.css        (any inlined styles)
```

Everything is compiled and minified. **Total size: ~600 KB** (mostly Recharts). Ready to distribute.

## Distributing to teammates

Any of these works:

**Zip the `dist/` folder and share it.** Teammates unzip and double-click `index.html`. Works because `base: './'` in `vite.config.js` produces relative asset paths — the file loads correctly from any location, including local filesystem (`file://`).

**Host on GitHub Pages.** Push `dist/` to a repo's `gh-pages` branch (or use the `docs/` folder pattern). Anyone with the URL can use it.

**Host on internal file share / static server.** Copy `dist/` to any location a web server serves. Nginx, Apache, S3, Netlify, Vercel — all fine.

**Note on fonts**: the `index.html` links to Google Fonts (Inter and JetBrains Mono). If teammates work in offline environments, they'll fall back to system fonts — the tool still works but looks different. To self-host fonts, either download them and modify `index.html`, or switch to system-only fonts by editing the font constants in `src/FlintExplorer.jsx`.

## File layout

```
flint3-explorer/
  package.json          ← dependency versions, scripts
  vite.config.js        ← build config
  index.html            ← page template
  .gitignore
  src/
    main.jsx            ← React entry point, mounts FlintExplorer
    FlintExplorer.jsx   ← the entire application (~2800 lines, single file by design)
  dist/                 ← generated by `npm run build`
```

`FlintExplorer.jsx` is deliberately kept as one file. Every component and helper is inline, making it easy to search, share, and understand as a single unit. Split into multiple files only if the file becomes unwieldy or the team wants to enforce module boundaries.

## Making changes

Edit `src/FlintExplorer.jsx` and save. If `npm run dev` is running, changes appear in the browser within a second (Vite HMR).

Common areas to modify:

- **Adding new metric categories** — see the `METRIC_GROUPS` constant near the top of the file
- **Colors and typography** — see the `COLORS`, `FILE_COLORS`, `CLIENT_COLORS`, `FONT_SANS`, `FONT_MONO` constants
- **Aggregation rules** — see the `primaryStats(hint)` function and the `statsFromValues` helper
- **Adding fields to client detail** — see the `ClientDetail` component
- **Adding new state-style metrics** — see `StateBlock` and its dispatch in `MetricCard`

When you're happy with changes, run `npm run build` to update the shareable version.
